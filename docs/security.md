# Security Design

Status: **Approved (Phase 2, 2026-10-17)** — kept up to date as phases are implemented
Last updated: 2026-10-17

Target baseline: OWASP ASVS 5.0 Level 2 (NFR-SEC-01). This document lists the threats we design against and the control for each.

## 1. Assets to protect

1. Member accounts and credentials.
2. Task, project and time data (business-confidential; time data is also personal data).
3. Attachments (may contain confidential designs or code).
4. GitLab access tokens and other integration secrets.
5. Audit log integrity.

## 2. Threats and controls

| # | Threat | Controls | Requirement |
|---|---|---|---|
| S1 | Password guessing / credential stuffing | Lockout after 5 failures, per-IP rate limit, minimum length 12 + breached-password list check, optional/required MFA, generic error messages | FR-AUTH-04/05/13, NFR-SEC-05 |
| S2 | Account enumeration | Identical responses and similar timing for login and forgot-password whether the email exists or not | FR-AUTH-06 |
| S3 | Stolen reset link | 256-bit random token, SHA-256 hash stored, 30-min expiry, single use, revoked when a newer one is issued or the password changes; link sent only to the account email | FR-AUTH-07/08 |
| S4 | Session theft | `__Host-` HttpOnly Secure SameSite=Lax cookie, 8-hour sliding expiry (configurable), security-stamp re-validation every minute, sign-out everywhere on password change/deactivation; no tokens in `localStorage` | NFR-SEC-02, FR-AUTH-11 |
| S5 | Cross-site request forgery | Antiforgery token in header for every unsafe method + SameSite cookie | NFR-SEC-03 |
| S6 | Cross-site scripting | Angular's automatic escaping; Markdown rendered with a sanitizer (no raw HTML); strict CSP (`default-src 'self'`; no inline scripts); `X-Content-Type-Options: nosniff`; SVG/HTML uploads blocked | NFR-SEC-04, FR-ATT-02 |
| S7 | Broken object-level authorization (IDOR) | Every query filtered by visibility rules; resource-based authorization in every handler; 404 for invisible records; integration test matrix per endpoint × role | FR-ROLE-05/06, NFR-SEC-09 |
| S8 | Privilege escalation | Permissions only from server-side role records; members cannot edit own roles; last-Admin protection; role changes audited; mass-assignment prevented by explicit DTOs | FR-MEM-05/06 |
| S9 | Separation-of-duties bypass | Self-approval rules checked in both authorization handler and domain method; tests for each | permissions-matrix |
| S10 | SQL injection | EF Core parameterized queries only; raw SQL only with parameters and reviewed; sorting/filtering by allow-list | — |
| S11 | Malicious file upload | Size limits enforced while streaming; signature-based type detection; random storage names outside web root; ClamAV scan before download; `Content-Disposition: attachment`; separate download path with no cookies needed for signed URLs | FR-ATT-02..07 |
| S12 | Path traversal | File names never used as paths; storage keys generated by the server | FR-ATT-04 |
| S13 | Secret leakage | Secrets only from environment variables / secret store; `.gitignore` + gitleaks secret scanning in CI; GitLab tokens encrypted with Data Protection and write-only in the API; logging filters redact `password`, `token`, `secret`, `authorization`, `cookie` | NFR-SEC-06 |
| S14 | Data Protection key compromise | Keys stored outside the database, encrypted at rest (certificate or cloud KMS), access limited to the app | database-design §3.11 |
| S15 | Information disclosure in errors | Problem Details without stack traces in production; exception details only in logs | NFR-SEC-07 |
| S16 | Audit tampering | Append-only by DB grants (`tma_app` cannot UPDATE/DELETE audit rows); audit written in the same transaction as the change | FR-AUD-03 |
| S17 | Time fraud | Server-side timestamps only; DB unique indexes against parallel sessions; sessions immutable; adjustments audited with reason | FR-TIME-02..04 |
| S18 | Forged GitLab webhooks | Per-link secret compared in constant time; payload used only as a trigger — the app re-fetches the issue from the GitLab API | FR-IMP-06 |
| S19 | SSRF via GitLab base URL | Only Admins can set it; `https` required (except allow-listed internal hosts); block link-local/metadata addresses (169.254.0.0/16 etc.); no redirects followed | FR-IMP-01 |
| S20 | CSV formula injection | Cells starting with `= + - @ \t \r` prefixed with `'` | FR-RPT-07 |
| S21 | Denial of service | Rate limits, request body size limits, pagination max 100, query timeouts, streamed uploads | NFR-PERF-02/03 |
| S22 | Vulnerable dependencies | `dotnet list package --vulnerable` and `npm audit` in CI fail on high/critical; Dependabot updates | NFR-SEC-08 |
| S23 | Clickjacking | CSP `frame-ancestors 'none'` | NFR-SEC-04 |
| S24 | Email content injection | Templates encode all user content; no user-controlled headers | FR-NOT-06 |

## 3. HTTP security headers (production)

```
Strict-Transport-Security: max-age=31536000; includeSubDomains
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:;
  media-src 'self' blob:; connect-src 'self' wss:; frame-ancestors 'none'; base-uri 'self'; form-action 'self'
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=()
```

Angular is built with `autoCsp`/no inline scripts; Angular Material's styles are bundled so `style-src 'self'` works. If a component needs inline styles, a nonce is used instead of `unsafe-inline`.

## 4. Secrets handling

| Secret | Where it lives |
|---|---|
| Database passwords | Environment variable / secret store |
| SMTP credentials | Environment variable / secret store |
| Data Protection key ring | Protected volume or cloud key store, encrypted |
| GitLab tokens | Database, encrypted with Data Protection |
| Webhook secrets | Database, hashed |
| Reset tokens | Database, hashed; raw only in the email |
| Development secrets | `dotnet user-secrets` (outside the repo) and `.env` files listed in `.gitignore` |

## 5. Logging rules

- Log member IDs, not emails or names, where possible.
- Never log request bodies of auth endpoints, cookies, `Authorization` headers, tokens, or file contents.
- Failed authorization attempts are logged at Warning with user ID, endpoint and resource ID.

## 6. Security testing

- Integration tests: authorization matrix (each endpoint × each role × own/other project), CSRF required, lockout, token reuse/expiry, upload type spoofing, headers present.
- CI: gitleaks, dependency scanning, CodeQL (GitHub) static analysis.
- Before production: OWASP ZAP baseline scan against the test environment; manual review against ASVS L2 checklist; results recorded in [known-issues.md](known-issues.md).
